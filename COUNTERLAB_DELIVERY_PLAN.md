## 1. Protect the defining capability

The ambition is an investigator that chooses experiments separating competing explanations. Preserve the chain: source evidence → explicit predictions → committed test → measured result → revised explanation → reproducible finding.

The first build sessions must establish scientific substance before presentation work. A polished source comparison alone does not pass. Choosing a vision without resource limits does not remove the actual submission date or guarantee that its first adapters can be built quickly.

## 4. Evaluation design

### A. Real cases

Record what was actually reproduced, discrepancies from the source protocol, numerical tolerances, and unresolved issues. Known public cases demonstrate workflow and fidelity; they cannot establish a novel discovery or contamination-free reasoning because the model may have seen their reports.

### B. Small diagnostic suite

Create 24 case variants across the supported adapters: eight development cases and 16 frozen evaluation cases. The latter contain four instances each of: metric/protocol differences with a resolvable mechanism; distinct regimes that can both hold; clean comparable results; insufficient or incompatible evidence. Treat these as a development benchmark with known limitations, not an external standard.

Ground truth comes from adapter invariants, explicit case construction, and independently computed numerical checks. Ambiguous real research conclusions are not assigned an artificial oracle label. Variants within one adapter are correlated and do not count as independent scientific domains.

The developer will necessarily know the case generator. Freeze evaluation manifests and scoring before final prompt tuning; hide answers and interpretation labels from the agent. Exclude answer-bearing report conclusions in diagnostic versions, while retaining the input facts needed to design the test. Keep those diagnostic conditions distinct from the normal source-aware product.

Three repeated agent runs per frozen case produce 48 runs per evaluated agent policy. Report outcomes by case and category, variation across repeats, cost, and latency. Do not treat all repeats as independent cases for statistical significance. If prompts change after evaluation, label the old suite reused and create fresh variants before claiming a new holdout result.

### C. Baselines

1. **Deterministic difference checker:** compares contract fields and units; no experimental planner.
2. **One-shot Nemotron analysis:** same input evidence, produces a plan/conclusion without observing new executions.
3. **Fixed or randomized experiment policy:** chooses from the same allowed experiments under matched execution and token/cost caps where applicable; shares the same final evidence summarizer.
4. **CounterLab:** adaptive test selection and evidence-dependent revision under that declared budget.

Report field extraction, protocol validity, conclusion correctness/coverage, unsupported conclusions, and useful tests per investigation separately. Do not invent a composite score favoring the product. For one-shot analysis, unsupported assertions count as such; being unable to execute is part of the baseline capability, not an adapter error. A second ablation can give the final summarizer identical accumulated evidence to separate selection quality from prose quality.

### D. Release targets

- Every displayed number links to a verified run artifact.
- Every completed run exports a replayable numerical record; reproduce representative real and diagnostic runs in a fresh environment.
- At least 40 of 48 frozen agent runs satisfy the predefined conjunction: valid protocol, properly scoped conclusion, and correct evidence references.
- Zero unsupported universal/theorem claims and zero fabricated execution evidence across the release suite.
- Abstention is evaluated on appropriate cases, rather than counted automatically as either success or failure.
- At least one real investigation satisfies G1 and has a justified evidence-dependent follow-up. A mechanism demonstration on the later checkpoint alone does not qualify.
- Demonstrate an advantage over the strongest simple baseline in correctness or useful testing efficiency before claiming the adaptive agent improves investigation. If there is no advantage, publish the null result and restrict the value claim to usability/reproducibility.

These are engineering release targets chosen before implementation, not literature-derived performance guarantees. A small suite cannot establish broad research reliability.
